## 一、问题分析

### 1.1 核心问题识别

根据产品现状分析，系统存在两个核心问题：

#### 问题一：输入错误频发
- **表现**：用户在Excel固定行列中输入数据时，经常出现格式不匹配和数据缺失的问题
- **具体场景**：
  - 列名与要求格式不匹配（如"库存表"而非"库存"）
  - 数据缺失（如需要30天销量，用户误输入平均日销量）
  - 数据类型错误（数值列输入文本）
  - 枚举值错误（卖场等级输入"A级"而非"A"）

#### 问题二：计算黑盒化
- **表现**：用户不清楚分配结果的计算过程和原因
- **具体场景**：
  - 用户不知道某个卖场分配5件的具体计算逻辑
  - 用户不了解四阶段算法如何影响最终结果
  - 用户无法追溯参数配置对分配结果的影响

### 1.2 用户需求优先级

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 分步骤数据验证与纠错 | 高 | 用户希望系统能帮助识别和修复数据输入错误 |
| 单个分配结果的计算细节 | 高 | 用户希望了解每个分配结果的详细计算过程 |
| 整体分配流程的可视化 | 高 | 用户希望看到四阶段分配的整体情况 |
| 保留现有快速导入流程 | 中 | 老用户习惯现有操作方式，不希望被强制改变 |

## 二、设计目标

### 2.1 总体目标

在保留现有系统核心功能的基础上，实现以下优化目标：

1. **输入错误率降低50%**：通过智能数据验证和纠错机制，减少用户输入错误
2. **计算透明度提升**：让用户能够清晰理解每个分配结果的计算过程
3. **用户体验优化**：提供双模式操作选择，适应不同用户的使用习惯
4. **向后兼容**：现有功能和工作流程不受影响

### 2.2 具体目标

| 目标 | 描述 |
|------|------|
| 智能数据验证 | 自动检测数据格式错误、列名不匹配、数据缺失等问题 |
| 一键修复功能 | 提供自动修复常见错误的能力 |
| Excel模板生成 | 生成标准格式的空白Excel模板，预防输入错误 |
| 计算过程追踪 | 记录分配过程中的每一步计算，支持追溯 |
| 流程可视化 | 展示四阶段分配的整体流程和统计信息 |
| 单个结果详情 | 点击单元格即可查看详细计算过程 |
| 双模式支持 | 提供快速模式和向导模式，满足不同用户需求 |

## 三、架构设计

### 3.1 系统整体架构

在现有系统基础上扩展，新增两个模块：

```
┌─────────────────────────────────────────────────────────┐
│                 allocation_app.py (GUI层)                │
│  ┌──────────┐  ┌──────────────┐  ┌──────────────────┐   │
│  │ 模式切换 │  │ 数据验证模块  │  │ 计算透明化模块    │   │
│  └────┬─────┘  └──────┬───────┘  └────────┬─────────┘   │
│       │               │                    │             │
└───────┴───────────────┴────────────────────┴─────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│              allocation_core.py (核心逻辑层)              │
│  四阶段分配算法  |  Excel读写  |  配置管理               │
└─────────────────────────────────────────────────────────┘
         ▲                        ▲
         │                        │
┌────────┴───────┐      ┌─────────┴──────────┐
│ data_validator │      │ calculation_tracker│
│      .py       │      │      .py           │
└────────────────┘      └────────────────────┘
```

### 3.2 新增模块说明

| 模块 | 文件 | 职责 |
|------|------|------|
| 数据验证模块 | `data_validator.py` | Excel模板生成、数据格式验证、智能纠错建议、验证报告生成 |
| 计算追踪模块 | `calculation_tracker.py` | 记录分配过程中的每一步计算、提供计算细节查询接口、生成流程可视化数据 |

### 3.3 核心设计原则

1. **向后兼容**：现有功能和工作流程不受影响，快速模式保持原体验
2. **渐进式披露**：高级功能默认折叠，用户按需展开
3. **错误友好**：不仅提示错误，还提供修复建议和一键修复选项
4. **可追溯**：每个分配结果都能追溯到具体的计算步骤和参数

## 四、双模式设计

### 4.1 模式定义

**模式1：快速导入模式（默认）**
- 与现有工作流一致：一次性选择Excel文件 → 执行分配
- 在执行分配前增加数据验证步骤（后台自动检查）
- 发现错误时弹出验证报告窗口
- 适合熟悉系统、数据质量稳定的老用户

**模式2：向导验证模式**
- 分四步引导用户导入和验证数据
- 每一步完成后即时反馈验证结果
- 支持跳过步骤（后续统一校验）
- 适合新手用户、数据问题较多的场景

### 4.2 模式切换设计

```
┌─────────────────────────────────────────────────────────────┐
│  加单商品分配系统                    v2.7.0 [关闭]           │
├─────────────────────────────────────────────────────────────┤
│  基于动态权重的库存补货与分配模型                              │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  ● 快速模式            ○ 向导模式                      │  │
│  │     一次性导入Excel，后台验证后执行分配                  │  │
│  └───────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
```

**交互逻辑：**
- 两种模式以单选按钮形式呈现，左侧为"快速模式"（默认选中），右侧为"向导模式"
- 下方显示当前模式的简要说明
- 切换模式时，主界面内容动态更新
- 系统记忆用户上次使用的模式（保存到配置文件）

## 五、数据验证与智能纠错设计

### 5.1 验证层级设计

采用三级验证策略：

#### 第一级：结构验证（Sheet和列名）
- 检查必需的4个工作表是否存在：库存、销售、卖场等级、加单数量
- 检查每个工作表的必需列是否存在
- **智能列名匹配**：当列名不完全匹配时，尝试模糊匹配
- 显示不匹配的列名列表，并提供映射建议

#### 第二级：数据类型验证
- 数值列检查：库存数量、销售数量、需分配数量是否为有效数值
- 文本列检查：卖场代码、条码/SKU是否为空
- 枚举值检查：卖场等级是否在 SA/A/B/C/D/OL 范围内
- 非负检查：所有数值是否 ≥ 0

#### 第三级：业务逻辑验证
- **30天销量检测**：智能判断销售数据是"30天销量"还是"平均日销量"
  - 启发式规则：如果大多数数值 < 5，则可能是平均日销量
  - 提供"自动转换为30天销量（×30）"选项
- **数据完整性检查**：
  - 加单SKU是否存在于库存表中
  - 卖场代码是否与卖场等级表一致
  - 是否存在重复的卖场+SKU组合
- **合理性检查**：
  - 库存数量异常大（超过历史销量10倍）
  - 销量为0但库存很高的异常情况

**交互逻辑：**
- 点击每个错误/警告项，高亮显示具体的行和列
- 对于可自动修复的问题，提供"一键修复"按钮
- 修复后数据实时更新到内存中，不修改原始Excel文件
- 用户可选择"忽略警告继续执行"或"修复后重试"

### 5.3 Excel模板生成器

**功能：**
- 一键生成标准格式的空白Excel模板
- 包含4个工作表，每个工作表有正确的列名
- 提供示例数据行（灰色提示，可删除）
- 每个列添加数据验证规则（如数值范围、下拉选择）

**模板包含的增强功能：**
- 卖场等级列：下拉选择（SA/A/B/C/D/OL）
- 数值列：设置为整数格式，禁止负数
- 颜色标识：必填列用浅黄色背景标记
- 说明Sheet：单独一个"使用说明"工作表，解释每列含义

### 5.4 向导模式步骤设计

**步骤1：导入库存表**
- 选择Excel文件或单独的库存Sheet
- 验证库存表结构和数据
- 显示库存统计（卖场数、SKU数、总库存量）

**步骤2：导入销售表**
- 验证销售表结构
- 智能检测30天销量vs平均日销量
- 显示销售统计（有销售数据的卖场/SKU数量）

**步骤3：导入卖场等级表**
- 验证等级表结构
- 检查等级值有效性
- 显示等级分布统计（SA: X个, A: Y个...）

**步骤4：导入加单数量表**
- 验证加单表结构
- 检查SKU完整性
- 显示加单统计（SKU数、总加单数量）

每个步骤都有"跳过"按钮，允许用户稍后补充。全部步骤完成后，统一执行最终验证。

- 每个参数值旁边标注其来源（如"安全系数0.5（SA级默认值）"）
- 显示参数变化对结果的影响（如"如果安全系数改为0.4，目标库存将变为8件"）

    └─ 验证失败 ──────▶ 显示验证报告（错误/警告列表）
                                │
              ┌─────────────────┴─────────────────┐
              ▼                                   ▼
        [忽略警告，继续执行]                  [修复后重试]
              │                                   │
              ▼                                   ▼
        执行分配（可能结果不准）              修复数据后重新验证
```

### 7.3 错误处理与用户反馈

**统一错误反馈策略：**

1. **即时反馈**：每个输入操作后立即验证并显示结果
2. **可视化提示**：使用颜色区分状态（绿色✓通过、黄色⚠警告、红色✗错误）
3. **详细说明**：每个错误/警告都有具体的说明文字
4. **修复建议**：对于可自动修复的问题，提供一键修复按钮
5. **操作引导**：按钮状态变化引导用户下一步操作

**关键交互细节：**

- **按钮状态管理**：
  - 未完成当前步骤：按钮为灰色不可点击
  - 验证通过：按钮变为蓝色可点击
  - 验证失败但可跳过：按钮变为橙色可点击，提示"跳过可能导致结果不准确"

- **验证报告交互**：
  - 点击错误项，跳转到对应的数据行
  - 展开/折叠各表的验证结果
  - 支持批量修复（如"修复所有等级格式错误"）

class ValidationResult:
    def __init__(self):
        self.passed = []      # 通过的验证项
        self.warnings = []    # 警告项

        self.fixed = []       # 已自动修复的项
    
    def add_passed(self, sheet_name, message):
        self.passed.append({"sheet": sheet_name, "message": message})
    
    def add_warning(self, sheet_name, row, column, message, fixable=False, fix_action=None):
        self.warnings.append({
            "sheet": sheet_name,
            "row": row,
            "column": column,
            "message": message,
            "fixable": fixable,
            "fix_action": fix_action
        })
    
    def add_error(self, sheet_name, row, column, message, fixable=False, fix_action=None):
        self.errors.append({
            "sheet": sheet_name,
            "row": row,
            "column": column,
            "message": message,
            "fixable": fixable,
            "fix_action": fix_action
        })
```

## 十二、风险评估

### 12.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 智能检测误判 | 将30天销量误判为平均日销量 | 设置阈值可调，提供手动确认选项 |
| 数据修复错误 | 自动修复导致数据异常 | 修复前备份原始数据，提供撤销功能 |
| 性能下降 | 验证和追踪增加计算开销 | 采用异步验证，优化算法复杂度 |

### 12.2 用户体验风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 界面复杂度增加 | 用户难以适应新界面 | 渐进式披露，默认只显示核心功能 |
